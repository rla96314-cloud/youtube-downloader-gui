# 방송 연동 다마고치 게임 기획서

> 작성일: 2026-08-19 · 상태: 초안(v0.1) · 문서 오너: rla96314

---

## 1. 한 줄 컨셉

**"시청자가 같이 키우는 펫"** — 스트리머 화면 위에 상주하는 다마고치를, 채팅과 후원(별풍선)으로 시청자가 함께 먹이고 놀아주고 진화시키는 방송 연출형 육성 게임.

핵심 차별점은 "혼자 키우는 다마고치"가 아니라 **육성 주체가 시청자 집단**이라는 점입니다. 펫의 상태가 곧 그날 방송의 시청자 참여도 지표가 되고, 성장/진화 결과가 방송 회차를 넘어 누적됩니다.

### 왜 이 컨셉이 방송에 맞는가
- **상시 화면 점유**: 게임 방송이 아니어도 오버레이로 항상 떠 있어 잡담/버츄얼/저스트채팅 방송과 충돌하지 않음
- **짧은 상호작용**: 후원 1건 = 1~5초 연출. 방송 흐름을 끊지 않음
- **장기 서사**: 펫이 성장/진화/사망하므로 "다음 방송에도 와야 할 이유"가 생김
- **후원 동기 부여**: 후원이 즉시 시각적 결과(밥, 진화, 스킨)로 바뀌어 기여감이 명확함

## 2. 타겟 & 플랫폼

| 항목 | 내용 |
|---|---|
| 1차 사용자 | 스트리머(SOOP/아프리카, 치지직, 유튜브 라이브) |
| 2차 사용자 | 시청자 (채팅 참여자, 후원자) |
| 실행 형태 | OBS **브라우저 소스**로 띄우는 웹 오버레이 + 스트리머용 로컬 컨트롤 패널 |
| 시청자 접점 | 채팅 명령어(무료) + 후원(별풍선/치즈/슈퍼챗) |
| 지원 해상도 | 오버레이 480×480 기본, 1920×1080 전체화면 모드 옵션 |

**플랫폼 선택 근거**: 데스크톱 앱(Tkinter/Electron)이 아니라 웹 오버레이로 가는 이유는 ⑴ OBS 브라우저 소스가 사실상 표준이고 ⑵ 알파 채널 투명 배경이 공짜로 되며 ⑶ 시청자용 웹 페이지(펫 도감, 기여 랭킹)를 같은 코드베이스에서 뽑을 수 있기 때문입니다.

## 3. 핵심 게임 루프

```
[시청자 행동]           [게임 반응]              [결과]
채팅 명령어    ──▶  스탯 소폭 변화      ──▶  펫이 반응 애니메이션
별풍선 후원    ──▶  스탯 대폭 + 재화    ──▶  연출 + 기여 랭킹 반영
시간 경과      ──▶  스탯 자연 감소      ──▶  방치 시 아픔/가출
누적 성장      ──▶  진화 조건 충족      ──▶  진화 연출 (방송 하이라이트)
```

**세션 루프(방송 1회, 3~5시간)**: 방송 시작 시 펫 기상 → 배고픔/청결 급함 → 시청자들이 채워줌 → 놀이/미니게임 이벤트 → 방송 종료 시 취침 연출 + 오늘의 기여 TOP 3 발표

**메타 루프(2~4주)**: 알 → 유아기 → 성장기 → 성숙기 → 완전체 → (수명 종료 / 계승) → 다음 세대는 이전 세대 유산 일부를 물려받음

## 4. 펫 시스템

### 4.1 스탯

| 스탯 | 범위 | 자연 감소 | 0이 되면 |
|---|---|---|---|
| 배고픔(Hunger) | 0~100 | -1 / 3분 | 체력 지속 감소 |
| 기분(Mood) | 0~100 | -1 / 5분 | 삐짐 상태, 명령 거부 |
| 청결(Clean) | 0~100 | -1 / 6분 | 질병 확률 증가 |
| 체력(Health) | 0~100 | 조건부 | 아픔 → 방치 시 사망 |
| 경험치(EXP) | 누적 | 감소 없음 | 진화 게이지 |
| 애정(Bond) | 누적 | 감소 없음 | 진화 분기 결정 |

> 감소 속도는 **방송 중에만** 흐릅니다. 오프라인 시간에는 스탯이 얼지 않으면 시청자가 없을 때 펫이 죽어버려 복귀 동기가 사라집니다. (오프라인은 "잠자기" 상태 = 정지)

### 4.2 성장 단계 & 진화

```
알 (0 EXP)
 └─ 유아기 (100 EXP)
     └─ 성장기 (500 EXP)
         ├─ 성숙기 A: 먹보형   ← 급식 기여 비중 최대
         ├─ 성숙기 B: 개구쟁이형 ← 놀이/미니게임 비중 최대
         ├─ 성숙기 C: 깔끔형   ← 청결 관리 비중 최대
         └─ 성숙기 D: 병약형   ← 방치/질병 이력 많음 (히든)
             └─ 완전체 (2000 EXP, 성숙기별 2종씩 = 8종)
```

**진화 분기 규칙**: 성장기 동안 누적된 "행동 유형 비율"이 가장 높은 쪽으로 확정 분기합니다. **랜덤 요소를 넣지 않습니다** — 후원이 결과에 영향을 주는 구조에서 확률을 섞으면 사행성 이슈(9.1절)로 직결됩니다.

### 4.3 사망 / 계승
- 체력 0 도달 후 **10분 유예**(응급 상태, 화면 경고). 이 사이 회복 시 부활
- 유예 초과 시 사망 → 묘지에 기록, 새 알 지급
- **계승 보너스**: 이전 세대 완전체 도달 시 다음 세대 초기 스탯 +10%, 스킨 1종 해금
- 사망 자체가 콘텐츠가 되도록 연출(추모 화면, 생애 요약, 기여자 명단)

## 5. 시청자 상호작용

### 5.1 무료 채팅 명령어 (참여 장벽 제거용)

| 명령어 | 효과 | 쿨타임 |
|---|---|---|
| `!밥` | 배고픔 +2 | 유저당 5분 |
| `!쓰다듬` | 기분 +2, 애정 +1 | 유저당 5분 |
| `!청소` | 청결 +2 | 유저당 10분 |
| `!펫` | 현재 상태 채팅 출력 | 전역 30초 |
| `!랭킹` | 오늘 기여 TOP 5 출력 | 전역 60초 |

**전역 상한**: 무료 명령어로 채울 수 있는 스탯은 시간당 총량 캡을 둡니다(예: 스탯별 +40/시간). 대형 방송에서 무료 명령어만으로 모든 스탯이 100 고정되면 후원 유인이 사라지고, 소형 방송에서는 반대로 아무도 안 채워줘서 펫이 죽습니다. → **동시 시청자 수에 비례한 동적 캡** 적용.

### 5.2 후원 상호작용

후원은 **확정 보상**만 제공합니다. 금액 → 효과가 1:1로 명시되고 랜덤이 없습니다.

| 후원 규모(별풍선) | 아이템 | 효과 | 연출 |
|---|---|---|---|
| 1~4 | 간식 | 배고픔 +10, 기분 +5 | 2초, 먹는 모션 |
| 5~9 | 정식 한 상 | 배고픔 +40, EXP +20 | 3초, 포만 모션 |
| 10~29 | 장난감 | 기분 +50, 애정 +10, EXP +50 | 4초, 놀이 모션 |
| 30~49 | 목욕 세트 | 청결 100, 질병 치료 | 4초, 거품 연출 |
| 50~99 | 영양제 | 체력 100 + 30분 스탯 감소 정지 | 5초, 전신 이펙트 |
| 100~ | 성장 촉진제 | EXP +500, 화면 전체 연출 | 8초, 풀스크린 |
| 1000~ | 진화 즉시 | 진화 조건 충족 시 즉시 진화 | 15초, 전용 컷신 |

**설계 원칙 3가지**
1. **소액이 무시당하지 않게**: 1개 후원도 반드시 고유 연출과 닉네임 노출을 받습니다. "1개는 아무것도 안 됨"은 후원 진입 장벽을 만듭니다.
2. **고액이 게임을 끝내지 않게**: 1000개 후원으로 즉시 진화하더라도, 다음 단계 진화 조건은 여전히 남습니다. 돈으로 콘텐츠를 소진시키면 장기 루프가 죽습니다.
3. **연출 시간 상한**: 연출 큐가 밀리면 방송이 마비됩니다. 대기열 길이에 따라 연출 시간을 자동 압축(최대 50%)하고, 동일 유저 연속 후원은 병합 연출합니다.

### 5.3 기여 랭킹
- **일간 / 세대별 / 통산** 3종. 세대별 1위는 펫에게 **닉네임 부여권**(욕설 필터 + 스트리머 승인 필수)
- 무료 명령어 기여도 별도 집계 → 후원 없이도 이름을 올릴 수 있는 트랙 유지

## 6. 후원 연동 아키텍처

### 6.1 핵심 설계: 플랫폼 어댑터 추상화

별풍선(SOOP)만 붙이면 플랫폼 종속이 생기고, SOOP은 서드파티용 공식 후원 API를 공개적으로 제공하지 않습니다. 따라서 **후원 이벤트를 정규화하는 어댑터 계층**을 먼저 만들고, 소스는 갈아끼웁니다.

```
┌─────────────────────────────────────────────┐
│  Adapters (교체 가능)                        │
│  ├ SOOP 채팅 WebSocket 파서                  │
│  ├ 투네이션 / 트윕 알림 위젯 리스너           │
│  ├ 치지직 도네이션 리스너                     │
│  ├ YouTube Live SuperChat (공식 API)         │
│  └ Manual / Mock (테스트·리허설용)            │
└────────────────┬────────────────────────────┘
                 ▼  DonationEvent (정규화)
┌─────────────────────────────────────────────┐
│  Game Core                                   │
│  중복제거 → 검증 → 아이템 매핑 → 스탯 적용    │
│  → 이벤트 로그(append-only) → 연출 큐         │
└────────────────┬────────────────────────────┘
                 ▼
┌─────────────────────────────────────────────┐
│  Renderer (OBS 브라우저 소스) + 컨트롤 패널   │
└─────────────────────────────────────────────┘
```

### 6.2 정규화 이벤트 스키마

```jsonc
{
  "eventId": "soop:20260819:8842301",  // 중복 제거 키 (필수)
  "platform": "soop",
  "type": "donation",                   // donation | chat | subscribe
  "userId": "hashed_user_id",           // 원본 ID는 저장하지 않음(해시)
  "nickname": "시청자닉",
  "amount": 10,
  "unit": "balloon",                    // balloon | cheese | krw
  "krwValue": 1000,                     // 내부 밸런싱은 원화 환산값 기준
  "message": "잘 커라",
  "occurredAt": "2026-08-19T13:04:22+09:00",
  "raw": { }                            // 원본 페이로드 보관(디버깅용)
}
```

**단위를 원화로 환산해서 밸런싱하는 이유**: 별풍선/치즈/슈퍼챗의 단가가 서로 다르므로, 게임 로직은 `krwValue`만 보게 하면 플랫폼이 늘어나도 밸런스 테이블을 다시 안 짜도 됩니다. 별풍선 단가·수수료율은 플랫폼 정책에 따라 바뀌므로 **설정 파일의 상수로 분리**하고 코드에 하드코딩하지 않습니다.

### 6.3 안정성 요구사항 (실제 방송에서 사고 나는 지점)

| 리스크 | 대응 |
|---|---|
| 후원 유실 (WS 끊김) | 재접속 시 마지막 처리 `eventId` 이후 재조회, 처리 못한 건 "지연 반영" 표기 후 적용 |
| 중복 적용 | `eventId` 기준 멱등 처리. 이미 처리된 ID는 무시 |
| 후원 취소/환불 | 보상 회수하지 않음(시청자 분쟁 유발). 대신 랭킹에서만 차감하고 로그 기록 |
| 연출 큐 폭주 | 큐 길이 임계치 초과 시 자동 압축 + 병합. 스트리머 "스킵" 핫키 제공 |
| 오버레이 크래시 | 상태는 매 이벤트마다 로컬 파일에 저장. 브라우저 소스 새로고침만으로 완전 복구 |
| 파서 깨짐 (플랫폼 UI 변경) | 어댑터 헬스체크 + 5분 무이벤트 시 스트리머에게 경고 표시 |

### 6.4 기술 스택 제안

| 레이어 | 선택 | 근거 |
|---|---|---|
| 오버레이 | HTML/CSS/JS + Canvas(또는 PixiJS) | OBS 브라우저 소스 표준, 투명 배경 지원 |
| 로컬 서버 | Python(FastAPI) 또는 Node(Fastify) | 이 저장소 스택과 맞추려면 Python 권장 |
| 어댑터 통신 | WebSocket 클라이언트 | 대부분의 채팅/도네 소스가 WS |
| 상태 저장 | SQLite (이벤트 로그) + JSON (현재 스냅샷) | 서버 불필요, 백업이 파일 복사로 끝남 |
| 배포 | 로컬 실행(단일 exe, PyInstaller) | 이 저장소의 기존 릴리스 파이프라인 재사용 가능 |

**클라우드가 아닌 로컬 실행을 권하는 이유**: 시청자 데이터를 외부 서버에 모으면 개인정보 처리 책임이 발생합니다. 로컬 실행 + 해시된 ID만 저장하면 대부분의 부담이 사라집니다.

## 7. 화면 구성

### 7.1 오버레이 (시청자가 보는 화면)
```
┌──────────────────────────────┐
│  ♥♥♥♡♡   Lv.3 성장기          │  ← 상단: 체력, 레벨
│                              │
│         ( ⌐■_■ )             │  ← 중앙: 펫 (도트 애니메이션)
│                              │
│  🍖▓▓▓▓░  😊▓▓▓░░  🧼▓▓░░░    │  ← 하단: 스탯 게이지
│  ────────────────────────    │
│  💬 시청자닉 님이 정식 한 상! │  ← 후원 알림 배너
└──────────────────────────────┘
```

### 7.2 스트리머 컨트롤 패널 (별도 창)
- 실시간 스탯 조정(사고 복구용) · 연출 스킵/일시정지
- 어댑터 연결 상태 표시등
- 이벤트 로그 뷰어 (누가 언제 뭘 후원했는지)
- 테스트 후원 발사 버튼 (방송 전 리허설)
- **긴급 정지**: 게임 전체 정지 + 오버레이 숨김

## 8. 개발 로드맵

| 단계 | 범위 | 산출물 | 예상 기간 |
|---|---|---|---|
| **M0** | 어댑터 골격 + Mock 소스 | 가짜 후원으로 스탯 변하는 콘솔 앱 | 3일 |
| **M1** | 오버레이 렌더링 | OBS에 펫이 뜨고 스탯 게이지 동작 | 1주 |
| **M2** | 실제 플랫폼 1종 연동 | 실제 후원 → 연출 (본인 방송 테스트) | 1주 |
| **M3 (MVP)** | 채팅 명령어 + 저장/복구 + 컨트롤 패널 | **실전 방송 투입 가능** | 1주 |
| **M4** | 진화 시스템 + 계승 | 2주짜리 메타 루프 완성 | 2주 |
| **M5** | 랭킹 웹페이지 + 도감 | 시청자용 외부 페이지 | 1주 |
| **M6** | 플랫폼 어댑터 추가 | 멀티 플랫폼 동시 지원 | 1주 |

**M3까지가 진짜 MVP입니다.** 진화 시스템 없이도 "후원하면 펫이 반응한다"만으로 방송에서 검증 가능하며, 여기서 밸런스 데이터를 모은 뒤 M4를 설계하는 편이 낫습니다.

## 9. 리스크 및 검토 필요 사항

### 9.1 ⚠️ 사행성 / 게임물 등급분류 (가장 중요)

**현재 설계는 의도적으로 확률형 요소를 배제했습니다.** 현금성 후원(별풍선)이 랜덤 보상으로 연결되는 구조는 국내에서 확률형 아이템 규제 및 게임물 등급분류 이슈로 직결될 수 있습니다.

지켜야 할 선:
- 후원 → **확정 보상만**. 뽑기/랜덤 박스는 무료 재화로만 운용
- 후원은 **스트리머에 대한 후원**이고, 게임 아이템 판매가 아님을 UI에 명시
- 획득한 아이템/펫에 **현금 환급·거래 기능을 넣지 않음**
- 배포 형태(공개 배포 vs 본인 방송 전용)에 따라 게임물 등급분류 필요 여부가 달라질 수 있음

> 이 문서는 법률 자문이 아닙니다. **외부 공개 배포 전에 게임물관리위원회 문의 또는 전문가 검토를 반드시 받으시기 바랍니다.**

### 9.2 플랫폼 약관
- SOOP/치지직의 비공식 채팅 파싱은 약관 위반 소지가 있을 수 있습니다. 공식 API 또는 투네이션·트윕 같은 **공인된 후원 위젯 경유**를 1순위로 검토하세요.
- 유튜브는 슈퍼챗 공식 API(Live Chat)가 있으므로 이쪽이 가장 안전한 검증 경로입니다.

### 9.3 밸런스 리스크
| 문제 | 증상 | 대응 |
|---|---|---|
| 소형 방송 | 아무도 안 먹여서 펫이 죽음 | 동접 비례 스탯 감소율 스케일링, 최소 생존 보장 |
| 대형 방송 | 스탯 항상 100, 후원 유인 없음 | 스탯 캡 대신 **누적 EXP·스킨** 쪽으로 후원 가치 이동 |
| 후원 도배 | 연출이 10분 밀림 | 큐 압축·병합, 동일 유저 연속 후원 통합 |
| 진화 조기 달성 | 2주 콘텐츠가 하루 만에 소진 | 진화 단계별 **실시간 방송 시간 최소 요구치** 병행 |

### 9.4 운영 리스크
- 닉네임 노출 → 욕설/광고 닉네임 필터 필수, 스트리머 차단 목록 연동
- 펫 이름 부여권 → 반드시 스트리머 사전 승인 게이트
- 개인정보 → 시청자 ID는 해시 저장, 원본 미보관, 로그 보존 기간 명시(예: 90일)

## 10. 확장 아이디어 (v2 이후)

- **펫 대전**: 다른 스트리머의 펫과 주간 대전. 스탯 기반 자동 전투 → 커뮤니티 간 교류 콘텐츠
- **시청자 개인 펫**: 웹에서 각자 펫을 키우고, 방송 펫과 상호작용
- **시즌제**: 시즌마다 진화 트리 교체, 시즌 종료 시 명예의 전당 등재
- **미니게임 이벤트**: 채팅 참여형(가위바위보, 숫자 맞추기)으로 무료 참여 트랙 강화
- **다운로더 연동(이 저장소 활용)**: 진화·사망 같은 하이라이트 순간을 자동 클립으로 저장 → 쇼츠 소재화
